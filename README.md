# Photo Detail Edit 使用说明

用一张原图和一段修改要求，完成摄影风格或背景编辑，再从原图补回能够可靠对应的主体细节。

适合人像、服装和物品照片的背景净化、棚拍风格、光影色调调整，以及透明背景抠图。默认先从 GPT Image 的结果学习局部 RGB 颜色和光影变换，再将变换应用到原尺寸原图，让真实细节呈现目标摄影效果；无法匹配的位置保留生成结果。

## 快速开始

在已经安装本 skill、且支持内置图片编辑工具的 Codex 环境中：

1. 上传原始照片，或上传包含原图的 ZIP。
2. 在消息中写明 `$photo-detail-edit`，附上希望实现的效果。
3. 等待完整流程完成，查看成片和局部对照。

可以直接复制下面的消息，并附上原图：

```text
使用 $photo-detail-edit 处理附件中的原图。

修改要求：改为杂志棚拍风格，净化背景，光线色调使用冷蓝光，侧面照射。
```

正常使用不需要自己编写脚本、绘制遮罩或补写保真 prompt，agent 会负责这些步骤。

## 准备原图

**细节恢复需要能够读取的原始图片文件。** 聊天中显示的图片预览可能被缩小；仅有预览时，无法恢复原文件中未传入的细节。

- 优先提供原始 JPG 或 PNG，避免用截图、聊天缩略图或反复压缩后的文件代替。
- 如果直接发送图片后只传入了缩小预览，可以把原图装进 ZIP 后作为文件上传。
- 使用远程环境时，图片需要对远程 agent 可读。只给出电脑上的 `C:\...` 路径，远程主机未必能访问；此时上传原文件或 ZIP。
- 不确定是否收到了大图，可以先说：“请先确认原文件的分辨率和文件大小，再使用这个 skill。”

skill 会读取 EXIF 旋转信息，并按照片正常显示的方向处理。默认保留原文件，生成独立的输出文件。

## 怎样写修改要求

描述希望改变的背景、摄影风格、光线方向和色调即可。若希望改变主体本身，也要写清楚，使恢复步骤知道哪些部位不应补回。

### 背景净化与自然棚拍

```text
使用 $photo-detail-edit：将背景整理成浅灰色无缝摄影棚背景，
使用柔和的杂志棚拍光线，保留人物、服装款式和自然肤质。
```

### 冷蓝侧光

```text
使用 $photo-detail-edit：改为杂志棚拍风格，净化背景，
光线色调使用冷蓝光，侧面照射。
```

### 去掉背景，输出透明 PNG

```text
使用 $photo-detail-edit：去掉背景，输出透明 PNG，
保留人物和服装的真实细节。
```

明确写“透明 PNG”可以区分抠图和替换为纯色背景。透明图片会保留生成底图的透明度，不另做会丢失透明度的 JPEG 成片。

### 有意改变某个部位

```text
使用 $photo-detail-edit：改为干净的棚拍背景，并去掉胸前的胸针。
保留其他服装和人物细节；胸针原位置不要从原图恢复。
```

换衣、删除饰物或重画某个物体等有意改动，会作为排除区域处理，避免后续恢复把修改撤销。主体改动越大，能够从原图可靠补回的范围通常越小。

## 它会自动完成什么

1. **检查原图。** 确认文件、像素尺寸、方向和透明度，建立本次输出目录。
2. **追加固定保真约束。** 在用户 prompt 后附上构图、主体细节和质量约束，再调用内置 GPT Image 编辑工具。
3. **比较原图与生成图。** 为需要保留的共同主体建立遮罩，排除背景和有意改动的区域。
4. **学习局部变换并应用到原图。** 将原图缩到生成图尺寸，用多尺度结构与线条趋势筛选可靠区域，减轻颜色、对比度和细纹理差异的影响。为各局部拟合平滑、保持单调的 RGB 颜色曲线，再把参数放大，作用于原尺寸原图。细节和目标色调一同变化；不匹配的位置沿用生成结果。
5. **检查并交付。** 提供完整尺寸成片、预览和局部对照，说明恢复范围与限制。

固定约束的核心是：

> 保持原来的构图；原图为全身照片时，保持原来的全身构图。保持纵横比，不裁切。尽可能保留原始细节，以支持的最高质量输出。人物及主体细节的忠实度优先于非必要的风格化效果。

完整内容见 [固定保真 prompt](references/preservation-prompt.txt)。它不会覆盖用户明确要求的改动，也不能保证生成模型逐像素保留主体。后续传统处理正是用来补回能匹配上的真实细节。

可以把新默认方案理解为“每个可靠小区域各学一套受约束的局部 LUT，再把规则用在原图上”。它是随位置变化的 RGB 颜色曲线，不是一张整图通用 LUT，也不从少量颜色样本强行拟合任意 3D LUT。相邻区域平滑衔接，以减少块状接缝。

普通多色照片默认用亮度结构判断对应关系；单一红光、蓝光等强单色照明则自动选择相应颜色通道。两张图使用相同的结构表示，不把红光示例的设置固定用于所有照片。以前的 Lab 灰度纹理叠加方式已不再是默认流程。

## 会收到哪些文件

每次任务会使用独立的输出目录。主要文件如下：

| 文件 | 用途 |
| --- | --- |
| `detail-restored.png` | 完整尺寸的无损成片；需要透明背景时使用这个文件。 |
| `detail-restored.jpg` | 便于分享的高质量 JPEG，仅非透明图片输出。 |
| `preview.png` | 较小的效果预览。 |
| `*-comparison.png` | 丝巾、织物、面部或其他主体细节的局部对照。 |
| 完整 prompt 文件 | 记录用户原文和实际追加的固定约束，便于复现。 |
| 生成底图 | GPT Image 的原始编辑结果，便于比较恢复前后的差异。 |
| `report.json` | 输出尺寸、匹配覆盖率，以及背景和透明度的检查结果。 |
| `local-transform-field.npz` | 小图上学习的局部曲线参数与可靠区域，供脚本回放；正常使用不需要手动编辑。 |

局部对照从左到右为：**放大的生成底图 → 对齐后的原图 → 细节恢复结果**。建议打开完整图片，以 100% 像素尺度检查布料、印花、皮肤和边缘；缩小预览不容易看出微小差别。

## 质量预期与限制

- **输出尺寸默认与原图一致，但不代表整张图恢复了原图的真实分辨率。** 背景和未匹配区域仍来自放大的生成底图，可靠对应区域则使用经过局部颜色变换的原图。
- 该流程以真实细节为来源，不使用生成式超分辨率，也不额外锐化。原图本身失焦或模糊时，不能补出原本不存在的信息。
- 生成模型若大幅改变姿势、脸部、衣物形状或图案，匹配范围会减少。没有足够可靠对应时，会保留生成结果，并说明未能有效恢复细节。
- 人物边缘、半透明发丝和强光区域会更谨慎处理，避免重影或把原背景带回来；这些区域可能仍较柔和。
- 新背景、目标色调、侧光和投影以生成底图为参照。默认方案学习局部 RGB 变换来重现这些效果，避免把原图灰度细节直接叠到强饱和光线上造成发灰。主体上的颜色和光影属于近似拟合，可能存在小幅偏差，需要与生成底图分别对照检查。
- 无损 PNG 的背景保持校验，以转换到 sRGB 并放大后的生成底图为参照。JPEG 是有损副本，不能用于逐像素一致性比较。
- 如果生成图的纵横比与原图相差超过 2%，脚本会停止，先检查构图，而不是把原图拉伸后硬配上去。
- 已验证的实拍案例包括同一原图的纯红极侧光换头版本和冷蓝侧光版本，并做了透明度、排除区域和无匹配输入的离线检查。这不代表所有照片或风格都已验证。冷蓝案例中，新方案的纹理与旧方案总体接近，丝巾局部细纹理相关度略低；采用新默认方案主要是为了改善强饱和光下的色度保持，并让细节随目标颜色一起变化。

## 安装

在实际运行 agent 的 Linux/macOS 主机上，可直接克隆到技能目录：

```bash
git clone https://github.com/eeoa/photo-detail-edit.git "${CODEX_HOME:-$HOME/.codex}/skills/photo-detail-edit"
```

下载本仓库或 skill 压缩包，将包含 `SKILL.md` 的文件夹命名为 `photo-detail-edit`，放到**实际运行 agent 的主机**的技能目录：

- 设置了 `CODEX_HOME`：`<CODEX_HOME>/skills/photo-detail-edit/`。
- 未设置 `CODEX_HOME`：`~/.codex/skills/photo-detail-edit/`。

正确的目录结构应包含：

```text
photo-detail-edit/
├── SKILL.md
├── README.md
├── agents/openai.yaml
├── references/
│   ├── preservation-prompt.txt
│   └── regions-and-running.md
└── scripts/
    ├── restore_detail.py
    ├── mapping_core.py
    ├── cv_core.py
    ├── requirements.txt
    └── self_test.py
```

注意不要多嵌套一层同名目录。远程会话应安装在远程主机上；只复制到本地电脑，不会同时安装到远程环境。若当前会话尚未发现新 skill，可在目标环境中开启新会话，再确认 `$photo-detail-edit` 是否可用。

### 运行条件

- Codex 会话具备可用的内置图片生成/编辑工具；skill 文件本身不提供 GPT Image 服务。
- Python 3.11+，以及 NumPy、OpenCV、Pillow。首次运行时 agent 会优先复用兼容环境，或在项目虚拟环境中安装 [依赖](scripts/requirements.txt)；安装依赖可能需要联网。
- 使用内置图片工具时，无需额外填写 OpenAI API Key；传统恢复脚本在本地执行，不联网、不下载模型。

只想正常使用时，不需要自己运行命令。需要手动维护脚本、调整区域配置或执行离线自检时，参阅 [区域配置与运行说明](references/regions-and-running.md)。

## 常见情况

**只有小图或聊天预览。** 提供原始文件或原图 ZIP；小图中已经丢失的信息不能作为真实细节恢复。

**不知道 prompt 该怎么写。** 从“冷蓝侧光”或“背景净化”的示例开始，修改背景、颜色和光线要求即可，保真约束会自动追加。

**看起来更自然，但没有更锐利。** 真实毛呢或皮肤纹理不一定比生成模型画出的规则颗粒更锐利。请结合原图局部对照判断，不只看锐度。

**有些区域仍然模糊。** 可能是原图本身不清晰、对应关系不可靠，或位于边缘保护区。可以指出具体位置，让 agent 检查遮罩和对齐；不应通过降低匹配门槛强行补回。

**希望再次调整风格。** 提供新的修改要求，并继续从原始照片开始；尽量避免把已生成、已恢复的成片反复当作新原图，以免累积改写和压缩损失。
